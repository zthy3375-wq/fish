# 社区数据库成本优化

分支 `perf/community-cloud-cost-20261119` 基于正式源码 main，独立于主题赛事分支。

## 优先减少空闲唤醒

CloudBase 的 PostgreSQL 共享实例以五分钟为计量窗口，窗口内发生数据库处理即产生计算用量。独享实例则按规格和运行时间计量。优化方向需要结合控制台的实例类型确认，不能仅按 HTTP 请求数估算 CU。

官方说明：[实例计量](https://docs.cloudbase.net/database/postgresql/database-management)、[上海地域计费](https://cloud.tencent.com/document/product/876/127357)。价格、优惠与实际点数以对应环境控制台为准。

- Android 社区取消三分钟一次的固定未读轮询。进入社区、回到前台、手动刷新或打开消息页时更新。
- 私信列表取消定时刷新。打开的会话保留八秒增量检查；没有用户互动或新消息两分钟后暂停，实际互动或重新进入前台后恢复。
- iOS 社区取消一分钟固定轮询，页面不可见时不因 App 回到前台读取未读。前台信号合并三十秒内的重复请求，主动下拉刷新仍可立即更新。

社区红点改为随进入、返回和主动刷新更新；空闲页面不承诺实时红点。

## 后台改动

- 合并未读接口直接复用本次鉴权后的成员，去掉嵌套 RPC 带来的第二次鉴权与持久限流写入。
- 新客户端用 `messages.read` 的 `withUnread` 可选字段取得全局剩余未读，减少一次 HTTP 与数据库调用。旧客户端保持旧响应路径，新客户端可回退兼容旧后台。
- 同一云函数实例内，并发 SQL 请求共用一次临时凭证兑换。兑换失败可以重试；切换服务端环境或密钥时不会复用旧凭证。SQL 写操作不自动重试。
- 上传时的孤立图片清理在同一实例内间隔十分钟；清理失败一分钟后可重试，满批次继续处理。用户删除、注销、撤回图片及管理删除仍立即执行原清理流程。

缓存仅在当前函数实例存活期间有效，没有增加数据库心跳、持久缓存服务或使用统计采集。会话、权限和内容可见性继续由服务端逐次校验。

## 验证与启用

`community-cost.verify.mjs` 验证重复限流写入、已读回执、清理时机、并发凭证兑换、失败重试和跨环境隔离。`community-idle-check.mjs` 用真实 Vue 组件和隔离传输夹具验证一小时空闲时新增请求为零，以及前台恢复、活跃会话和闲置后暂停。

已增加原生未读请求合并测试，保留真实数据库的消息发送、旧服务回退、失败重试和分页回归。

后台生效需要部署 community 云函数并更新 `hyt_community` SQL 函数；客户端停止轮询需要安装对应版本。没有新增业务表或改写现有用户数据。开发验证与线上生效分开记录，真实 CU 节省量必须在部署后对比控制台用量。
