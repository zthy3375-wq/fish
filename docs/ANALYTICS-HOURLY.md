# 统计小时汇总

授权背景：个人版每月40000点；此前 PostgreSQL 8.79核时耗尽免费3000点。降低持续零散访问，避免以云函数内存或临时目录作为可靠队列。

## 行为

- Android 原接口和凭证不变，服务端只持久化凭证摘要。已登记安装的摘要索引迁入私有对象存储；新登记仍由 PostgreSQL 校验后写索引。
- 普通 record：验证日期/版本/白名单字段及凭证摘要索引后写不可覆盖的队列对象，成功后才答复200。相同累计快照去重；对象存储失败答复503，不确认丢失数据。
- 每小时定时器调用受独立密钥保护的 flush。合并相同设备/日期的累计最大值和最高版本，SQL 再次验证已有设备凭证；没有注册行的排队记录不能重建账号。
- 事务提交并成功保存汇总快照后才移除队列对象。SQL、快照发布失败保留对象；重放按最大值合并，不叠加次数。每轮最多2000对象，达到上限返回 limitReached，积压可能延迟超过一小时。
- stats 只读对象存储快照，刷新不调用 PG。跨北京时间午夜未新汇总时，今日数返回null，前端显示待汇总；超过75分钟显示汇总延迟。凌晨空队列仅在日期变化时重算一次。
- delete 即时删除数据库与授权索引并更新汇总，旧排队记录在 SQL 凭证关联时被排除，不会复活。并发中已开始的请求可能短暂写入队列，下一轮消费后清理；队列不进入管理报表或公开访问。
- 新增有界预发布版本格式支持，避免测试包版本被旧校验拒绝。

## 部署

分支 fix/analytics-hourly 的工作流先测试模拟故障和真实 PostgreSQL，再验证对象读写/匿名403、迁移已有设备摘要及快照。先部署 canary 并验证登记、排队、汇总、真实计数和删除，再部署小时定时器和正式统计函数。正式切换后验证失败恢复旧版函数，队列保留。不会重建/清空数据库，不修改更新函数与蒲公英发布清单。

对象均位于现有云存储的 hyt-analytics-v2/ 前缀，ACL private。定时函数与 HTTP 聚合端不打印安装ID、凭证、SQL返回行或云密钥。注册/删除属于少量即时数据库访问，无法承诺严格仅有24个计费窗口。对象存储、云函数、存储容量和异常重试另计；约1.03万点/月仅为每小时单个5分钟计算窗口的理想模型，需以实际用量验收。

## 验证状态

本地18项合约、持久暂存、失败回放、跨日快照和版本校验通过。云上部署与真实数据库合并测试待CI，完成后记录实际结果；尚不宣称节省已实现或账单达标。
