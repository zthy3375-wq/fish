# 社区主流程设计记录 · 2026-11-17

本轮在既有浅紫白体系内延伸社区信息流、详情、评论和写作流程。产品范围见 [BRIEF.md](BRIEF.md)；保留首页／课表／社区／待办／我的五 Tab、系统中文字体、主题选择和独立社区身份规则。没有替换品牌、增加字体／框架／插画、建立第二套全局 token，亦未改变后端 schema、账户权限或存储格式。本记录只沉淀社区局部实现；根 `DESIGN.md`、`.impeccable/design.json` 与 `PRODUCT.md` 保持原状。

## 已落地的构成

| 区域 | 当前实现与用途 |
| --- | --- |
| 信息流导航 | 广场／关注／继续聊置于浅底分段容器，选中项为白面和深主色；按钮至少 44px 高。当前五分区同排显示，旧后端的分区容器保留溢出横向滚动；选中项使用共享淡紫底与深主色，不增加导航层级。 |
| 帖子阅读 | 作者、时间、分区在前，标题／摘要、媒体、互动依次排列。帖子左右 18px，信息流内边距为 16px 18px 10px，帖子间用 8px 页面底色分隔；静态白面不叠投影。互动前留 8px、上内边距 6px，并以细线分组。 |
| 摘要与详情 | 摘要标题最多两行、正文最多三行，实际溢出才显示“展开全文”。摘要正文 16px／1.75、标题 18px／650；详情正文 17px／1.85、标题 23px／650／1.5。详情正文可选择，保留换行和长词换行，不把信息流裁切带入全文。 |
| 评论与楼中楼 | 评论区以 8px 底色带与正文分开，标题边距为 18px。顶级评论上下 20px、头像与内容间隔 12px；正文 16px／1.8。楼中楼使用浅强调面、左侧细边界和右侧 10px 圆角；作者与“回复谁”单独成行，正文 14px／1.8，预览最多三行。保留全部回复、加载更多与收起操作。 |
| 详情底栏 | 白色固定阅读操作栏，最小高度为 64px 加底部安全区；回复入口、点赞／收藏／评论保持可识别。入口与图标动作至少 44px，窄于 375px 时缩小边距和间隙，保留正文空间。 |
| 发帖写作 | 身份与发布分区在写作面之前，标题和正文合为连续无边框区域。标题 21px／1.6，正文 17px／1.85、最小高度 152px；说明与草稿状态为 12px。工具组用浅底和 12px 圆角，最小高度 52px，附件操作至少 44px。 |
| 图片与附件 | 待发图片采用横向滚动的 96px 缩略图带、10px 间隙，保留顺序、选中、移除和前移／后移。单图显示正在上传／已上传／上传未完成，失败图用危险色轮廓。沿用最多九张帖子图片、三张评论图片及既有投票／招募条件。 |
| 回复编辑 | 回复对象在输入前以浅强调面呈现，上下文预览最多三行；输入正文 17px／1.8、最小高度 96px、最大高度 32dvh。弹层上限为视口减顶部安全区和 12px，底部发布区粘性定位并允许换行，匿名与发送入口至少 44px。配图入口为图标在上、数量在下的居中组，间隔 4px。 |

组件图形保持紧凑，44px 是操作命中区域的要求。已落地的帖子菜单、评论点赞／菜单、展开／收起、回复、阅读栏动作、分区、附件工具和失败重试均按此组织；不从本次局部修改推导所有历史控件已完成同一验收。小屏断点沿用 374px，主要调整导航内边距和横向间隙，不引入新字号体系。

## 主题、状态与恢复

颜色来自 `src/tokens.css` 的语义变量：浅色校园紫、白色阅读面、浅紫灰底和淡紫强调面沿用既有值；深色继续使用既有冷灰蓝覆盖。社区没有新增共享颜色、字号、间距、圆角或动效 token。发布浮钮沿用主题主色背景，前景改为 `--color-raised`，使浅色紫底保留浅字，深色浅蓝底使用深字与深色笔形；展开与收起状态共用同一配色。

上传反馈由 `TreeholeUploadStatus.vue` 持有，使用 `role="status"`、`aria-live="polite"`，区分图片上传、帖子／回复发布和失败，显示实际已上传数量。失败保留文字、图片与请求 ID；普通重试复用已上传图片，服务明确返回图片不可用时才清除对应远端上传引用。失败区提供就地重试，不能用完成勾或成功文案掩盖尚未完成的发布。

草稿写入按账号、账号轮次和内容修订版本检查，串行保存快照；编辑后先显示“保存中…”，仅当前修订实际写入成功后显示“草稿已保存”。失败显示保留当前页面的提示与“重试保存”；“保存草稿并返回”等待保存成功再离开。身份说明与分区限制保留：发布后身份固定，树洞统一匿名，回复延续已有匿名隔离规则。

现有按下反馈、键盘焦点和 reduced-motion 继续生效：帖子按钮焦点为 2px 主色轮廓，低动态偏好关闭相关过渡、点赞和上传旋转动画。原生返回、输入法及安全区仍由既有框架协作，浏览器短屏样例不替代 Android 输入法验收。

## 样式所有权与资产来历

`src/tokens.css` 持有全局语义值；`Treehole.vue` 最后加载 `TreeholeRedesign.css`，由它持有社区导航、详情栏、写作区、回复弹层和本轮两项修正。`TreeholePostCard.vue` 与 `TreeholeCommentThread.vue` 的 scoped 样式持有阅读节奏、正文层级和回复链；`TreeholeUploadStatus.vue` 持有发布状态呈现。

原有 `Treehole.css` 通用 label 规则已排除评论配图 picker，局部 `.treehole .th-comment-photo-editor>label` 明确持有垂直居中布局，避免通用表单标签再次覆盖附件控件。新增页面应复用语义变量和组件所有权，不把这些局部覆盖提升为全站样式。

校园摄影、小金鱼与宋体横幅属于所有者要求保留的既有首页资产，继承关系来自 `PRODUCT.md`、根 `DESIGN.md` 和首页设计记录；仓库既有校园图为 `public/art/campus-autumn.webp`。本轮社区没有生成或引入校园艺术资产，社区截图中的帖子图片属于合成测试内容。所读资料未提供原校园图摄影者、原小鱼作者或许可溯源，本记录不补写推测，也不将社区截图视为首页资产的重新验收。
