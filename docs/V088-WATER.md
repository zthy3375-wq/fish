# v0.8.8 原生接水

## 流程与状态

扫码 → 选择实际出水口 → 查询付款方式 → 确认按实际用量使用 → 启动请求 → 同订单用水状态 → 机身或支持机型远程结束 → 同订单后付结算 → 核对实付账单。

准备只读最新details、skus与payChannelRoute/afterPay，不选择支付方式或开水。确认页60秒有效，绑定原生持有的设备和SKU，不接受前端任意设备、订单或金额。启动前重新核对设备、程序、付款方式和可用性，费率/描述/出水口名称变化要求重新确认。固定支持已开通、可用的method15支付宝免密；返回需要开通或未知可用性时不发启动请求。显式官方入口使用既有官方支付宝小程序appId，不传token，不自动签署协议。用户须核对该小程序的胖乖手机号。

goods/water/unlock前加密保存启动意图；响应丢失不会再次启动。回包中的orderNo立即保留，msgId用于machine/msg/sync查询。state=OK/code=0仅说明命令响应，同orderNo的identify且status=1/workStatus=2才进入“接水中”；不声称这能证明物理水阀一直流动，暂停按机身操作。

匹配identify且status=5/workStatus=1确认设备结束。另兼容JUWPHub已记录的机身结算后data=null：曾核对同订单使用中，且连续两次业务成功但空data，按平台会话关闭收尾并查询同订单账单；界面标注会话消失依据，并提示仍出水时立即按机身结算，不能把它当作水阀传感器证明。单次空值或未曾确认使用不触发结算。goods/endWater执行前重新读同步状态、匹配订单，再读取supportAppUserFinish；仅明确true放行。endWater受理后继续等设备结束，平台拒绝或响应未知提示机身结算，不自动重发。没有远程暂停接口证据，不提供假按钮。

物理或远程结束后按启动时确认的本次后付授权结算：amount明确零时跳过后付；未知/非零走order/afterPay/creating和order/sync。amount单位未知，不当作费用或水量。两种后付命令各自在发送前持久化标记，后续仅查询原单或完成尚未发出的下一步，不重建或重复扣费。结算前核对order/detail中的订单、设备和SKU；账单orderStatus 2/3和payPrice用于确认实付，同时必须已确认设备结束才显示本次已结算。

返回其他identify或尚不满足上述空会话规则时，不操作该设备，尝试只读本人账单。未知启动且无orderNo时，提供显式“已按机身结算，核对设备”：仅设备返回结束空闲状态或业务成功但无会话时关闭本地未知记录，不发送结束或结算命令，不声明账单成功。正常有orderNo的记录仍按同订单核对。若服务端迟迟不再返回本次设备状态，保持待核对，不直接放行下一次启动。

## 持久化与界面

胖乖原有独立加密vault保存water，JS快照仅包含展示字段。关闭页面、进后台停止轮询；重新打开继续原单，同账号续登保留，退出/换号清理本机状态，不发送结束或解约。每3秒前台读取，连续3次失败停止自动轮询，保留手动查询。与洗衣状态独立，可同时保留一笔洗衣和一笔用水，原生请求串行。

时长为首次确认使用后的本地参考计时，不能当作计费依据。查看到结束后显示实际账单金额；零用量不显示伪造0元。当前不做后台自动结束、后台提醒、其他免密渠道、远程暂停或优惠资产使用。

## 验证覆盖

原生：准备无副作用、渠道不可用、设备忙、启动确认绑定、命令确认与使用分离、启动丢响应不重发、物理结束模式、远程结束受理不等于结束、零用量、未知用量、其他订单不结束、两段结算各自丢响应、账单身份核对、支付状态不代替设备结束、桥接字段隔离。
