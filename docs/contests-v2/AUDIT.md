# 主题赛事 2.0 审计

基线：PR97 e3edce0 为赛事源码，PR100 c74f72d 为交付APK源码（测试合并e1bbcd5），PR99 30dcbc3 为实际部署的schema13后台。30dcbc3与c74f72d的src/android/ios-native相同。此次从30dcbc3建立refactor/theme-contests-v2-20261120，不从main覆盖，也不部署、合并或改更新通道。

## 已从调用链确认并回归验证

- Hub的type、year、contests同时服务本期和历史；切回本期仍带type条件。
- vote先写投票，再get详情，最后才更新voted，第二步失败会把已成功的投票显示为失败。
- compose每次重置内存稿；没有持久草稿；编辑已有图片仅留ID。
- 结束赛事open默认winnersOnly=true；普通作品被默认隐藏。
- themes审核采用selected.id或列表第一个赛事ID；SQL会按该赛事读锁、写审核日志并可能重结算；scheduler也会做无关查询。
- 单纯注册未满7天或2秒内连续投不同作品就写risk，tick/announce对所有risk硬阻断，正常用户可拖住自动公布。
- 管理保存后不确认发布，管理操作缺少请求ID去重；nonce能保护投稿，但编辑内容变化后继续用旧nonce存在冲突风险。
- list/profile仅有缓存，无并发去重；返回对象直接共享，旧读响应可能在写入之后重新填入缓存。
- get不返回我的作品、vote不返回权威投票状态；新界面需兼容已部署schema13，后端增量修复单独待部署。

## 重构约定

首页只有当前比赛和作品墙，历史/主题征集为次级入口，管理只对开发者显示。主操作由服务器时钟和我的作品决定。作品卡只做封面、标题与作者，进入详情再投票。投稿独立页面，本机草稿按账号/赛事/作品隔离，有离开确认、图片逐张重试和稳定投稿nonce；成功直接进入自己的作品。

管理创建只露出名称、主题、封面、3/7/14/自定义周期、格式及发布，默认7天。原全部参数折叠高级设置。管理中心与创建分开，危险操作确认并提供原因；结果以服务端确认，副刷新失败不误报写失败。

数据不删除不回填改票。迁移只增字段、索引和管理请求账本。保留旧risk作为审计信号，年龄与正常3次快速选择不再单独阻断结果；高频反复切票采用可复核的窗口计数。新老客户端和schema13均走现有action，新增响应字段可选，旧后台使用本地确认值兼容。
