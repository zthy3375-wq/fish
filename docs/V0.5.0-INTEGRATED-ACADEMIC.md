## 实现

`HandanAcademicPlugin.kt` 实现 Capacitor `HandanAcademicClient`：login/getSessionState/getProfile/getSemesters/getTimetable/getGrades/getExams/syncAll/logout。学校 WebView 没有 Capacitor 或 JavascriptInterface；Vue 不接触 Cookie、密码、Token。登录只在官方页面进行。学校来源限制为精确 HTTPS origin，TLS 错误取消，学校 console 输出拦截，不收集原始网络日志。

会话由 CookieManager 保持；另用 Android Keystore AES-GCM 加密保存仅此学校 origin 的 Cookie，弥补进程退出时 session cookie 的持久化差异。不保存密码、不绕过验证码。会话仍由服务器决定是否有效；已过期会话不能靠本地保存续期。退出清理原生会话与学校缓存，个人课表/备份不动。此 APK 使用 debug 签名，不是正式商店签名。

学校查询逻辑是 APK 内固定的 `handan-academic.js`，不是下载执行远程适配器。先读取学校实际课表页面的学年/学期选项和现有菜单链接，再携带同一 WebView 会话请求。候选端点必须通过数据结构检查；课表拒绝异常行，缺教师/教室留空。实际返回 xsxx 学期值时核对与请求相同。能定位到周、天、节次的实践课进入网格；无具体时间的实践课单独显示，不编造时间。

`AcademicSyncEngine` 先提交课表，随后独立查询成绩与考试；首次登录完成课表后自动开始记录同步。单次同步合并重复触发，启动优先读本机缓存，前台恢复有2分钟节流，支持下拉/按钮刷新。学校数据按学期独立缓存，不写入个人课表数据库；内容匹配保留课程/安排 ID。空响应、异常、部分解析失败不覆盖上次成功课表。退出过程使在途结果失效，成功重新登录启用新的账号缓存，不混用前一个账号资料。

正常导航：首页 / 课表 / 教务 / 我的。成绩、考试、学籍使用真实查询结果或空状态；移除正式界面原有模拟成绩、培养方案、手动课表读取、诊断与覆盖确认。个人事项、个人文件导入和备份继续在个人数据管理中提供。

## 本轮接口证据边界

2026-11-06：直接打开官方登录页面成功，显示邯郸学院及 V-9.0。未输入用户凭据。云端浏览器没有本任务需要的完整请求调试接口，使用用户要求的 APK 会话级联调路线。

以下仍是候选契约，**没有邯郸学院已认证响应证据**：

| 模块 | 候选请求 | 数据结构门槛 |
| --- | --- | --- |
| 课表 | GET 页面 + POST `/kbcx/xskbcx_cxXsgrkb.html` | 学校页面 xnm/xqm，JSON kbList，逐条课名/周/天/节次；有界 HTML 网格回退 |
| 作息 | POST `/kbcx/xskbcx_cxRjc.html` | 数组 jcmc/qssj/jssj，连续合法节次和时间；否则保留此前13节作息 |
| 成绩 | POST `/cjcx/cjcx_cxDgXscj.html?doType=query` | 分页 items，kcmc/cj/xf/jd；等级成绩保留原文 |
| 考试 | POST `/kwgl/kscx_cxXsksxxIndex.html?doType=query` | 分页 items，kcmc/kssj/ksrq/cdmc/zwh；空安排不当作登录失败 |
| 学籍 | 课表响应 xsxx | 只取姓名、专业、班级、年级，缺失留空 |

模块码仅作为标准 V9 候选，菜单中存在实际链接时优先采用。服务器返回非标准 module/route、隐藏的动态菜单、特殊验证码域、表单 CSRF、校外认证域或不同分页字段时可能需要继续适配。当前没有扩大学校域名白名单。

学期选项来自学校页面，但**第一教学周日期仍复用本机校历配置**；本轮未验证学校校历接口，历史学期若没有相应本机校历不能宣称日期准确。UI 标注“教学周按本机校历”。学校作息接口与夏冬季切换也待真机确认。

成绩/考试候选请求及 GPA 字段支持已编码，未实测。iOS 工程保留；Swift 学校会话实现未开发，iOS UI 明确提示尚待适配。

## 最小真机操作

安装测试 APK，打开首页点“连接邯郸学院”，在官方页面完成一次登录（如有验证码由本人完成）。程序随后自动查询，不需要检测、读取、导入或确认保存。回到首页看课程，再完全关闭重开观察缓存与后台刷新。成绩和考试各自显示时间/失败状态；如果失败，只需反馈界面显示的状态或截图，不需要导出文件或分析请求。

不要卸载旧诊断版以尝试安装：旧版 `org.handancampus.app.diagnostic` 与当前 `org.handancampus.app` 可以共存。各包的数据隔离；旧包中的个人数据继续保留，原备份恢复仍可用。若同包出现签名冲突，先保留原包与备份，不以卸载作为默认步骤。
