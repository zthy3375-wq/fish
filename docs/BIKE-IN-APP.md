## 官方来源与核对方法

读取公开官网及它们实际引用的页面脚本，不登录、不发送短信、不提交申请、不调用开锁/还车/支付接口；没有提取 App 凭据、修改设备签名或探测内部环境。脚本中出现的测试服务地址没有被请求。只把页面声明、代码观察和业务推断分别记录。

### 哈式骑：有 H5 产品说明，缺少普通哈啰单车适用证明

- [哈式骑首页](https://saas.hellobike.com/)确实介绍其他 App、网页内用车，列出 H5、小程序、MPaaS 等接入形式。
- 实际首页组件 [index-0b739a5a.js](https://saas.hellobike.com/index-0b739a5a.js) 同时展示小品牌入驻和多个地方品牌案例。这个上下文支持“面向合作运营”的判断，**不能据此认定仅限合作车队，也不能反向认定普通哈啰车已开放**。
- 本次下载的首页组件中，两个“权限申请”按钮均未配置 `onClick` 或 `href`，未发现可用的 H5 自助申请表、价格、个人开发者条件、生产骑行入口或接口文档。此为当前静态页面观察，不是平台拒绝接入的回执。
- 首页实际链接的 [微信入口](https://saas.hellobike.com/open-weixin.html) 和 [抖音入口](https://saas.hellobike.com/open-douyin.html)进一步读取其引用组件：分别用于小程序授权给发布系统。它们不是普通用户把哈啰骑行账号授权给邯院通的流程，不能冒充用户登录。
- 没有取得 H5 运行环境清单。第三方 WebView、登录后车辆参数保留、定位授权、蓝牙桥接、实名/支付回跳、退出返回及 Cookie 隔离均待平台文档及测试环境验证。

### 哈啰通用开放平台：存在合作接入文档，不等于单车权限

[门户](https://m.hellobike.com/AppHelloOpenApiPortalWeb/latest/index.html)实际引用的 [app.214e47d9.js](https://m.hellobike.com/AppHelloOpenApiPortalWeb/PRO/0.0.2/js/app.214e47d9.js)含公开说明：

- [注册文档](https://m.hellobike.com/AppHelloOpenApiPortalWeb/latest/index.html#/doc/access/register)：按企业/B 端账号体系注册；没有在这份文档中找到个人开发者准入承诺。
- [应用管理](https://m.hellobike.com/AppHelloOpenApiPortalWeb/latest/index.html#/doc/access/create-app)：新应用审批启用后才能使用；分配 appKey/appSecret，Secret 需要二次确认查看。
- [服务订阅](https://m.hellobike.com/AppHelloOpenApiPortalWeb/latest/index.html#/doc/access/subscribe)：每个应用另行订阅已开放的具体服务。

- 合作方登录文档提到 7 天 Token，但未取得普通共享单车的用户授权范围、刷新/撤销合同和骑行接口，不能将通用登录返回值当作骑行权限。
- 同一个门户的单车卡片仍处于不可点击的待开放状态。通用文档里出现的顺风车示例和回调说明不移植到单车业务；过往文档中的 HTTP 回调说明也不足以成为新接入的安全合同。

因此不调用通用合作方登录进行试探，不把 appKey/appSecret 写入客户端，也不构建一套猜测的授权接口。

### 美团：官方骑行入口明确，公开企业用车文档不证明单车接入

- [单车隐私政策](https://rules-center.meituan.com/m/detail/guize/24?activeRule=1)介绍官方 App/小程序中的账号、定位、扫码/蓝牙、订单及支付处理，属于官方产品的能力说明，未提供本项目可直接使用的第三方开锁授权。

- 未找到适用于样本 `b=8646834293_1` 的、允许普通第三方 App 嵌入的骑行 H5/SDK 或公开账号授权与开锁/还车 API。此为本次公开检索结果，不作“平台绝不开放”的断言。

### 还车与计费

[美团单车租赁协议](https://rules-center.meituan.com/m/detail/guize/183?activeRule=1)要求使用者在官方页面确认关锁结果；未成功归还可能继续产生费用。[美团电助力车型规则页](https://bike.meituan.com/mtbike/spock_ride_rules/zh/index.html)另有手机还车说明，但不能把某车型规则直接用于照片中的车辆。

两张静态车码照片不足以确定具体锁型和当地还车流程。手动合锁、手机控制落锁、停车点校验及异常结束均以实际车型的官方页面为准，不能统一承诺远程关锁。车锁状态、订单状态和支付状态需单独确认；关闭网页、退出邯院通、Intent 分发成功或 HTTP 200 都不能证明停止计费。

## 取得接入条件后的实施方案（尚未实现）

### 路线 A：官方 H5/SDK

优先实现官方提供的完整流程，标题标识服务商，保留返回/退出。扫码 ticket 在原生校验后依文档交给批准入口。页面只运行在独立、明确允许的官方来源中；不向它暴露 Capacitor 主桥或任意 URL 启动能力，不为适配登录伪造宿主 App 身份。

先确认 WebView 支持、允许来源/回调、会话有效期及注销、账号切换、定位与蓝牙需求、支付返回、实名/人脸支持，再实现按需权限。若该 H5 要求支付宝/微信容器或专有桥，就使用对应官方容器；这仍属于外部官方用车，不能宣称留在邯院通内。

### 路线 B：批准的 API

最小架构为现有 Android 客户端、HTTPS 服务端、加密保存授权的最小数据存储及可验签回调入口。服务端保存合作密钥，按正式合同处理授权交换/刷新/撤销、幂等操作、订单查询与回执；客户端只持有自己的短期会话，凭据不进入 Vue、日志或 APK。授权失效/换账号立即隔离旧状态，进行中的官方订单仍以官方查询为准。

当前调查新增云成本为 0。未来 H5 是否需要服务端、API 合作费及沙箱费未知；后端可先评估已有腾讯云环境承载，不再先开一套数据库。没有接口调用频率、订单量与平台报价，暂不填造月费或承诺固定成本。

### 状态与异常合同

| 界面状态 | 必须具备的证据/行为 |
| --- | --- |
| 已识别车辆 | 仅本机二维码通过白名单且用户可核对车号 |
| 待授权 | 平台接入已启用，当前账号缺少正式授权；尚未接入时不展示假的账号连接流程 |
| 请求处理中 | 用户明确点击，记录幂等请求关联；禁止重复点击和后台自动发起 |
| 骑行中 | 官方订单查询/验签回执确认账号、车号与订单处于使用中 |
| 还车待确认 | 用户提交了正式还车操作，尚未收到可靠最终确认 |
| 已结束 | 官方订单终态确认；支付是否完成单独显示 |
| 状态未知 | 超时、回调缺失、冲突或过期；保留最小订单线索、查询及官方处理入口，不声称停止计费 |

先查询再决定下一步，任何有副作用的开锁/还车操作不盲目自动重试。应用恢复先核对当前账号和订单，不因页面返回、刷新或进程重启重新开锁；取消授权、退出账号和账户切换不视作还车。

获得批准后才新增相应测试：授权取消/过期/撤销、账号隔离、重复点击、网络超时后订单查询、回执重复/乱序/签名错误、进程恢复、还车终态及支付独立状态。合成测试只验证程序逻辑，真实开锁、付费、停车点/锁型和骑行由用户在现场确认。
