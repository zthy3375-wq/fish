# 应用内快递取件测试版

基于稳定版 1.2，当前开发 1.2.1-test.2 / 135（test.1 为 134），仅交付测试 APK。首次在官方网页完成登录及验证码；没有把打开页面当作登录或同步成功。test.2 新增“全部待取”原生列表，只汇总前台本次已打开网页的可识别取件码。入口为首页校园生活的“取快递”。

## 本轮实现

- 新的原生 Activity 提供淘宝、拼多多切换、刷新、返回、关闭、官方原始页面和固定官方 App 备用入口。两个平台按需建立 WebView，切换保留文档，后台暂停，关闭销毁展示内容。会话由 WebView 保存，不转交前端、不读 Cookie；test.2 的固定只读脚本经 evaluateJavascript 返回 station/code 与阶段枚举，只在 :parcel_web 进程内存展示，不保存码、原始响应或页面到文件/日志/统计。
- 淘宝先显示官方身份码页面；只有真实码图片加载且无登录表单/认证 iframe 时，应用同源页面布局。复用官方来源 iframe，展示真实身份码、待取列表和独立刷新，不伪造条码。
- 拼多多在文档开始前对指定官方 API 来源进行同源代理路由映射，登录/验证码页面不改写。官方包裹区域出现后才整理。登录落入官方首页最多尝试一次返回取件入口，不无限重定向。暂用顶部整页刷新，不展示无法工作的组件级刷新按钮。
- 更多菜单可直接查看官方待取/身份码页，或重新整理。没有推荐内容清理失败时仍可打开原页的兜底路径。官方 App 导流与未经核对的地址由导航白名单拦截，用户可用固定 App 按钮继续。
- Activity 无 Capacitor/JavaScript 原生桥。登录弹窗仅允许用户手势触发，并沿用同一平台 HTTPS 导航范围；拒绝相机、定位、上传、下载和任意 scheme。没有关闭 TLS 校验或伪装官方 App UA。

## 网页隔离与清理

只在 `:parcel_web` 进程、Android 9+ 调用 `setDataDirectorySuffix("parcel_web")`，由 Application.attachBaseContext 在任何 WebKit 初始化前完成。失败不降级使用教务共享目录。完整清理依赖系统 WebView 的 DELETE_BROWSING_DATA 特性；不支持时显示官方 App 入口。主进程与胖乖独立目录均不改变。

清除快递登录需确认，范围包括本机淘宝、拼多多两个快递 WebView。先持久化 pending 标志、销毁所有快递网页，再调用 WebStorageCompat.deleteBrowsingData，完成回调后才可重开；中断后下次启动先清理。不会退出官方 App、清除教务/学习通/钱包或执行服务器解绑。

拼多多网页登录与官方 App 可能互相使会话失效；页面已提前说明，不承诺永久登录。

## 交付与验收

自动检查覆盖前端入口并发/迟到回调、官方登录判断、PDD 映射范围与请求参数保持、导航白名单等，另需原生编译与 Release 测试。计数和具体 APK 来源在 STATUS.md 记录。

实际待验证：两个平台分别登录与验证码、真实非空待取件、条码出库、重新打开与覆盖安装会话、登录弹窗、号码管理、拼多多 SPA 返回、刷新、后台恢复、单独快递清理后教务/钱包不受影响。无真实账号测试不宣称已经完成接入验收。test.2 已增加按平台/驿站的部分结构化取件码列表，缺失字段保留“未识别”并提供官方页核对；不从身份码、手机号或运单猜测。原生与 DOM 两侧限制数量、字段长度与码格式；不回传 Vue、跨进程、备份或统计。后台、导航、刷新与清除会话使读取回调失效，后台清除内存结果及放大弹窗。尚未实现离线取件码、自动标记取走或通知监听。
