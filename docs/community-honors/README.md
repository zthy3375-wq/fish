# 社区身份与成就 · Android test.26

设备沿用 test.25 包名 org.handancampus.app、原签名、versionCode 176。个人主页与我的社区均可打开荣誉殿堂。广场及评论最多显示一种身份和一个所佩戴荣誉。匿名投影直接省略成员 ID 与徽章。公开主页只返回自选三项的名称和日期，私人进度归本人。利用 Android 原生加密会话发起请求。浅色收藏柜支持筛选、详情、减少动画、震动和提示音。

## 数据和判定

数据库沿用 hyt_members 的 UUID。开发者时间戳有唯一索引。管理员沿用旧角色，四项范围分别为内容、举报、用户和推荐。种子永久保留，创作者推荐后由开发者审核。授权事务写入 hyt_honor_history，管理页面显示最近 30 条。重复操作由请求 UUID 去重，数据表和内部函数禁止普通角色直接访问。

hyt_honors 保存当前荣誉，hyt_recommendations 保存待审，hyt_awards 以成员和成就为唯一键。自选荣誉与成就置于成员记录。首批八项基于账号、帖子、评论、点赞、收藏。重复正文或相同讨论只获得相应的一份信用。两个字符以上的非重复有效评论或已确认的配图能计入。新注册账号在首 24 小时给同一作者的点赞，按 UTC 日最多合计一个成就进度；普通点赞显示数量不受影响。历史点赞缺少可验证来源时不计。删除、撤回或移除内容会扣减当前进度，已解锁记录永久保留。旧账号在首次登录后进入社区或查看自己的收藏时按可验证记录补发，既往实际达成日期未知时标记为历史补发。

四项后续规则保留为特别收藏，当前不授奖，未计入八项分母。最初的相遇对应种子荣誉，闪闪发光对应创作者荣誉，众人瞩目对应单篇一百个有效赞，邯院传说对应十五项其他成就。隐藏条件不会出现在未解锁详情。

## 运行成本

关键路径借用原业务 RPC 和同一数据库事务，发帖、评论、点赞和收藏均不新增云函数调用。普通列表通过成员行和所佩戴荣誉主键投影，无逐作者网络请求。达成后的同类指标跳过再核算，首次补发仅处理当前账号。打开收藏柜为一次云函数、一次数据库 RPC。过期刷新失败可显示当前会话最近的私人柜。解锁确认延后合并；无新解锁时没有确认调用。付费成本依赖真实写入量、热点和套餐，未加入行为统计、定时扫描或页面上报。

## 开发者绑定

1. 所有者登录原社区账号，在「社区 → 头像 → 成就反馈设置」查看本人的社区成员 ID。
2. 通过受信运维环境将其设置为 CONFIRMED_OWNER_UUID。使用已有受保护的 CloudBase 服务凭据运行 node scripts/cloudbase/bind-developer.mjs。账号 ID 仅标识目标，授权证明来自历史数据库中的原始所有者授权审计。无需提供密码、恢复码或登录令牌。
3. 脚本在事务里同时核对 2026-11-16 的唯一所有者记录、稳定 ID、账号有效性和管理员状态。任一不符自动退出。授权成功会创建审计，重跑幂等，客户端没有绑定入口。重新打开社区即可展示皇冠。日常授权从「我的社区 → 身份与荣誉管理」进入。

## 迁移与验证

scripts/cloudbase/honor-migration.mjs 生成单事务升级，匹配已知旧 RPC 摘要，保留已有业务行和授权；原角色不自动升为开发者。事务中只处理荣誉与所需管理能力，沿用正在运行的数据库与云函数。迁移演练命令为 node scripts/cloudbase/verify-honor-migration.mjs <旧版 schema SQL 文件>。业务和权限回归为 node --test --test-concurrency=2 cloudbase/tests/community*.mjs。三种手机宽度的前后截图与交互走 Community honor gallery verification。
