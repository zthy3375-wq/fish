### 公开证据的复核方法

执行 `node scripts/inspect-public-academic.mjs`。仅访问上面的固定公开登录地址一次 GET，禁止自动跟随跳转；20 秒超时、1 MB 响应上限；不提交认证、不爬取资源、不尝试猜测路径。不保留 Cookie、CSRF、密码、二维码或 SSO 地址，仅输出存在性/是否为空、公开版本、摘要和选定响应头。失败只报告失败，不尝试替代接口。

本轮成功结果保存在 [research/handan-public-observation-2026-11-06.json](research/handan-public-observation-2026-11-06.json)。观察时间、HTTP 200 与 SHA-256 可追溯；登录页可能包含动态值，后续摘要不同并不自动说明平台升级。`authorizationProtocol: not-established` 是研究状态，绝不是学校返回的协议名称。

研究检索范围包含 `site.hdc.edu.cn` 的“统一身份认证/正方/第三方/接口/OAuth/OIDC/CAS/导出”，以及官方首页、教务处、登录页和拾光源码。其他高校的 OAuth、正方接口示例不能作为邯郸学院已开放服务的证据。`idp.hdc.edu.cn` 的公开搜索记录和本轮直接访问超时同样不能建立其与教务的集成关系。

## 3. 真正可以自动同步的路线及缺失条件

### 优先：学校批准的身份授权 + 本人只读数据 API

只有学校确认实际支持后才能实施，当前没有可填的真实端点或 client ID。流程为：

1. 学校登记 fish 的应用标识、平台回调/域名、最小本人课表 scope、测试条件与访问限制。
2. 学生点击绑定，交给学校认证页面；若学校支持 OAuth/OIDC 原生应用流，则采用系统浏览器、授权码 + PKCE、state（OIDC 另校验 nonce/issuer/audience）。依据 [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252)，不以可注入脚本的嵌入式 WebView 代替 OAuth 外部用户代理。
3. 只调用学校确认的“当前登录人”接口；不能让客户端随意传学号换取他人数据。返回学期、周次、作息及课表，经过解析与预览，用户确认保存到独立来源分区，本机个人课表不被覆盖。
4. 后续按学校允许频率刷新；有官方刷新授权时按规范续期，失效/撤销/权限不足时停止请求、清授权视图，提示重新到学校登录；绝不保存密码、从 WebView 提取 Cookie 或反复试探接口。
5. 学校若只提供 CAS/SAML 登录，仍需另行批准并提供只读数据服务；登录成功或拿到身份断言本身并不会提供课表 API。公共 Web 客户端不可保管 client secret，学校若要求机密客户端须单独评审服务端，不能硬塞进前端。

所谓“自动”首先指用户授权后手动/前台刷新无需重复录课；**定时后台持续同步另受 iOS/Android 调度限制，不保证永久后台运行**。原生凭据须用 Keychain/Keystore 等受保护存储，Web 凭据策略与 CORS 也需按学校接口设计评审，不能放 localStorage/课表备份。现有 v0.4 授权快照仅内存显示，还不具备这一真实授权数据离线分区；本轮没有为未知凭据实现假存储。

### 次选：学校明确允许的官方页面内主动导入

如学校没有第三方 API，但明确允许学生在官方页面主动导入本人课表，可单独评审限域、限定顶层页面、仅导入课程数据的原生桥接。用户手工登录/验证码，采集后预览保存，退出清理会话，绝不注入登录页或转存 Cookie。先拿允许范围、脱敏 DOM/JSON、作息和原生测试条件再写平台实现。它可减少手工录入，但**不是长期自动同步**，不能作为本次已经打通的交付。

### 当前确实可用的替代

保留个人课表、CSV/XLSX/ICS 导入和版本化备份。若学校允许导出文件，学生可在学校页面自行导出后本机导入；当前没有证据能确认学校学生端具体导出格式。不要让用户上传密码、Cookie、二维码、抓包 HAR 或完整响应日志。

## 4. 本次实际代码及验证边界

- `src/services/academic-adapters/zhengfang-timetable.ts`：无网络、无认证、无存储的离线 `kbList` 格式适配。严格识别全部周次表达式，单双周/自定义周、多安排归组、准确作息映射，复用现有预览、重复及冲突提示。明确标为 `offline-format-preview / not-verified`，不返回“登录成功”。
- 学期和作息必须显式提供；不猜学期开学日、学期码、默认时长或课程节次。来源含学期码时必须提供完全匹配的已确认编码；有未适配实践课或未知结构时拒绝静默丢弃。教师/教室缺失留空并告知。
- 文件入口限制 UTF-8 JSON 1 MB、500 条安排、字段长度/周次/节次范围；无 eval、动态脚本、DOM 执行或远程请求。未知字段白名单剔除；任何行错误均留在 preview.errors，未来调用方必须阻止带错误的提交。空课表不构成清空指令。
- 只作为研究模块导出，**没有加入正式导入列表**，避免把 JSON 备份和未确认的正方导出混淆。原 CSV/XLSX/ICS 路径、用户偏好及 schema v2 均不改动；默认真实连接器仍为空。
- `scripts/inspect-public-academic.mjs` 及观察 JSON：可重现的公开页检查，保留脱敏事实，不提交原始登录 HTML。
- `tests/fixtures/academic/zhengfang-synthetic.json`：手工构造的格式样本，绝非邯郸账号响应；测试内 13 节作息也为人工示例，绝非学校现行作息。
- 回归覆盖：完整语法/越界/未知周次、单双周、多安排、13 节作息、缺失作息、学期不符、异常记录、重复/冲突、空课表、超限/错误编码/脚本内容、无网络与凭据剔除；经既有 CRUD、共享首页选择器、v0.4 标准化、IndexedDB 和备份往返验证格式链路。**这只能证明本地代码和格式，不是账号归属或真实同步测试。**

## 5. 距离真实账号可用还缺什么

| 需要学校教务处/信息化部门确认 | 用途 |
| --- | --- |
| fish 作为第三方读取本人课表的允许范围、学校对接负责人及接口使用约定 | 确立允许的技术边界与维护渠道 |
| 认证协议、真实地址/metadata、客户端登记、回调、scope、测试环境 | 才能实现登录和回调验证；仅有登录 URL 不够 |
| 本人课表只读接口与脱敏样本、字段/错误码、访问频率、撤销与会话续期规范 | 完成可维护的数据 transport，验证 ownership 和过期处理 |
| 现行学期/教学周、作息表、调停课/实践课和特殊周规则 | 避免课表“导入成功但时间错误” |
| 若无 API，是否允许官方页面内主动导入，以及学生可导出的实际格式 | 决定是否开展限域桥接或特定文件解析，而非冒充持续同步 |
| 经同意的本人测试账号由学生在学校页面亲自操作、Android/iOS 测试条件 | 完成首次绑定→查询→保存→刷新→过期→重新登录的真实验收 |

可以把本表作为对接材料交给学校；本次没有代用户联系、提交申请或收集账号。得到这些信息前，保留当前无连接器状态，不能把“真实账号自动同步”视为已完成。
