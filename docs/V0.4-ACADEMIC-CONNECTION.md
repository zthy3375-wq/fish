# v0.4 教务账号连接：已实现边界与未实现事项

## 当前状态

本分支实现了**可审核的、学生本人授权范围内的教务连接框架**，并非已接通邯郸学院教务系统。

- 学生可在「教务 → 官方教务」查看连接状态、学校官方网页入口。
- 已增加授权连接器契约、状态机、严格的学期/课程/成绩/考试白名单数据校验。
- 接入符合契约的连接器后，授权同步的数据显示在首页、周/日课表、成绩与考试页面；脱离连接后恢复既有演示或个人课表。已同步的学校数据**仅存在本次运行内存**，尚无持久化离线缓存。
- 原有本地课表、备份、导入、演示模式、Android/iOS 工程不被替换。
- **当前无有效的邯郸学院第三方接入协议、token 发放规则、回调注册或只读教务 API 文档，因此没有注册实际连接器，也不能在 fish 输入学号密码并自动同步。**
- 官方登录页链接仅让用户在学校自己的站点登录查看，不代表 fish 已获得授权。不要在未验证的第三方网页提交教务密码。

## 代码组织

- `src/services/academic-connection.ts`：`AuthorizedAcademicConnector` 接口、连接状态机、数据规范化及来源隔离。
- `src/services/authorized-connector-registry.ts`：仅接受明确注册的已审核连接器，默认 `null`。
- `src/components/AcademicConnection.vue`：真实连接状态/官方入口；没有连接器时不展示不可用的登录/同步按钮。
- `src/components/AcademicDetail.vue`：教务连接页面，以及授权数据的课表/成绩/考试来源标记。
- `src/App.vue`：仅在成功同步后切换官方数据视图；不覆盖 `ScheduleState` 本地个人课程。
- `tests/academic-connection.test.ts`：模拟授权连接器、校验、过期和失败路径。

## 真正接通学校需要的资料（不能猜测）

1. **允许第三方客户端使用的认证方式**（OIDC/OAuth2 或经过学校明确许可的其他方式）、客户端注册、回调 URI、允许的 scope、授权/登出/刷新规则。
2. **学生本人只读的数据接口规范**：学期/教学周、个人课程与节次、成绩、考试，包含数据结构、错误、分页、时间规则。
3. **访问限制与隐私要求**：学校服务条款、访问频率、日志、密钥管理、撤销授权和学生申诉渠道。
4. **可用的联调账号和测试环境**，或经学校允许的学生本人测试流程。

### 后续对接步骤

- 新建一个独立的 `handan-authorized-connector` 模块，实现 `AuthorizedAcademicConnector`。
- 登录交由学校认证页完成。支持 OAuth/OIDC 时，在 Android/iOS 使用系统浏览器和 Authorization Code + PKCE，以及注册的应用回调。不要在前端打包 client secret。
- 在 App 启动入口显式注册连接器，获得授权后仅请求当前用户的只读数据。
- 把学校响应转换成 `normalizeAuthorizedAcademicData` 所要求的结构。学校数据不存在的字段应由受审核的适配层明确处理，而不是编造。
- 同步通过后，增加加密的本地缓存、有效期/数据过期提示、撤销清理和断网测试，再声称离线支持官方数据。
- 增加学校允许的请求频率及错误重试策略，完成 Android/iOS 真机认证返回、安全测试。

## 安全底线

不在 fish 自建账号密码表单；不记录密码、Cookie、会话 token；不在源码/日志中存放学校密钥；不绕过验证码或认证；不自动抓取未向第三方开放的端点。

学生能在学校网页查看自己的数据，并不自动构成第三方客户端可调用学校 API 的授权。

## 验证说明

CI 测试覆盖模拟连接器及数据源边界，不等于真实学校联调通过。未经学校联调前，所有用户界面均必须显示「未接入学校授权接口」。
