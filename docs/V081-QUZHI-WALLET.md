# v0.8.1 趣智校园钱包

本轮按用户确认的顺序只接入趣智钱包。胖乖扫码饮水、洗衣以及淘宝/拼多多出库码留到后续逐项交付。

## 用户入口与范围

- 今天页和我的页的「校园生活 → 趣智校园」。不改现有课表、待办和学习通导航。
- Android 原生手机号/密码或短信验证码登录；成功后先查询钱包验证会话，再保存。凭证输入不经过 JavaScript bridge。
- 账户总余额、充值余额、赠送余额分别展示。缺失字段显示「—」，不把未知金额当零，不猜总额。
- 按北京时间月份读取消费账单；本轮只保证消费 DTO 的展示，不宣称已接入充值流水。
- 点击充值并确认当前账户信息后，直达支付宝的趣智小程序充值页面。小程序使用其自身的登录账户，用户付款前必须核对学校与手机号。
- 返回应用后重新查询余额。打开页面、返回、余额变化都不会生成「充值成功」订单；到账由平台记录确认。
- 注销清除趣智会话和缓存；个人待办、学校与学习通缓存保持独立。

## 实现

`QuzhiCampus` Capacitor 插件拥有原生登录 UI、固定 HTTPS 查询、Keystore AES-GCM 会话和快照存储。Vue 只得到脱敏手机号、学校名、金额、消费记录、更新时间和固定错误类别。

请求限定 `v3-api.china-qzxy.cn` 的六条已研究路径，不跟随重定向、不跳过证书验证、不自动重试、不记录响应正文。短信冷却从发起时开始，避免超时后连续发送。密码、验证码不落盘；Android 备份已禁用，登录窗口禁止截图。

钱包、学校名、账单独立处理失败。网络错误/格式变化保留各自成功快照；跨月失败标明旧账单所属月。会话失效后停止余下请求。单月超过 200 条时明确标记只显示前 200 条。

## 验证边界

- 原生单测：登录响应形态、金额精度、未知金额、错误分类、账单格式变化、部分失败、跨月缓存、会话失效停止请求。
- Web 单测与 360/390/430 像素人工原生替身 UI：连接、金额、充值取消/发起、失败保留、过期、退出、存储隔离。
- Android debug/release 编译及原生测试由本轮构建检查记录提供。
- 尚未使用真实趣智账户执行登录、短信、查账和充值，也未通过邯郸学院账户/运营商兼容验收。最终需要用户在 APK 中登录并核对余额、支付宝账户和真实到账。
- 2026-11-08 仅做一次无凭证钱包 GET 连通性检查，HTTP 200 / `success=false` / `errorCode=8` /「未获取到用户信息，请重新登录」。此形态已加入原生失效识别回归；这不是登录或钱包数据验收。
- 独立测试包 `org.handancampus.app.life.v081`，保留旧应用；测试签名不能保证覆盖以前的测试包。
