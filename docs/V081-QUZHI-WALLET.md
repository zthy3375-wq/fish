# v0.8.1 趣智校园钱包

本轮按用户确认的顺序只接入趣智钱包。胖乖扫码饮水、洗衣以及淘宝/拼多多出库码留到后续逐项交付。

## 用户入口与范围

- 今天页和我的页的「校园生活 → 趣智校园」。不改现有课表、待办和学习通导航。
- Android 原生登录默认密码方式；切换短信时明确提示可能由趣智平台注册新账户，必须勾选确认后才能提交。成功后先查询钱包验证会话，再保存。凭证输入不经过 JavaScript bridge。
- 余额仅按明确单位字段展示：money 为元，accountMoney 为整数厘（千分之一元），两者冲突则保留旧记录。accountRealMoney/accountGivenMoney 的单位在参考项目间不一致，暂不展示充值/赠送分项，避免千倍误报。缺失金额不当作零。
- 按北京时间月份读取消费账单；本轮只保证消费 DTO 的展示，不宣称已接入充值流水。
- 点击充值并确认当前账户信息后，直达支付宝的趣智小程序充值页面。小程序使用其自身的登录账户，用户付款前必须核对学校与手机号。
- 返回应用后重新查询余额。打开页面、返回、余额变化都不会生成「充值成功」订单；到账由平台记录确认。
- 注销清除趣智会话和缓存；个人待办、学校与学习通缓存保持独立。

## 实现

`QuzhiCampus` Capacitor 插件拥有原生登录 UI、固定 HTTPS 查询、Keystore AES-GCM 会话和快照存储。Vue 只得到脱敏手机号、学校名、金额、消费记录、更新时间和固定错误类别。

请求限定 `v3-api.china-qzxy.cn` 的六条已研究路径，不跟随重定向、不跳过证书验证、不自动重试、不记录响应正文。短信冷却从发起时开始，避免超时后连续发送。密码、验证码不落盘；Android 备份已禁用，登录窗口禁止截图。

钱包、学校名、账单独立处理失败。网络错误/格式变化保留各自成功快照；跨月失败标明旧账单所属月。会话失效后停止余下请求。单月超过 200 条时明确标记只显示前 200 条。

## 接手复核补充

对照 quzhi-lite 固定提交 `29463db5395c7c2cbcf45411a627e2ee9bb57b9d` 的 QuzhiApi.kt，确认 accountMoney 是整数厘，消费账单 consumeMoney 仍按元。只借鉴协议事实，不复制未授权源码。新增单位冲突、非法金额保留缓存、扁平 v3LoginCode 登录回归。更完整开源比较见 [OPEN-SOURCE-STRATEGY.md](OPEN-SOURCE-STRATEGY.md)。

生命周期复核：新的原生实例和销毁事件会使旧实例失效，所有会话恢复/保存/退出与所有权切换共用锁，旧网络请求不能在新实例退出后重新写回凭据。短信冷却按手机号保存在进程级状态，取消后重开登录窗口不会重置 60 秒冷却。
