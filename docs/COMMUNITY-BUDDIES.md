# 搭子招募 · test.12

基于 `feat/community-polls-comments-20261116` / PR #72 / `8a1349a`，保留 test.11 全部成果。开发分支 `feat/community-buddies-20261116`，Android `1.3.0-test.12 /162`、原包名和原正式签名，原生 iOS 最低 iOS 16。仅测试，不合并 main，不更新蒲公英或正式更新渠道。

## 已实现

- 搭子广场可添加活动时间、集合地点与 1–20 个额外名额；人数不含发起人，时间统一北京时间，限未来 90 天。
- 原普通搭子帖保持；新招募允许匿名，需写活动说明，与投票互斥。发布后时间、地点和人数固定；字段随账号草稿保存。
- 报名/退出、招满提示、开始时间截止、发起人结束/重新开放招募；并发报名由数据库帖子行锁保护，不超卖。
- 「我的社区 → 我报名的」返回已报名帖子；报名进入「我参与的」，默认关注讨论，但尊重主动取消关注。
- 名单仅发起人可看，只有昵称、头像、公开标识与报名时间，无登录账号；报名按钮事先说明此可见范围。匿名发起人的身份不返回给报名者。
- 报名/退出通知发起人，关闭/重新开放通知已报名者；按讨论合并应用内消息，仅泛化身份。点击消息回到原帖。
- 账号切换丢弃迟到结果；前端和原生 iOS 用服务端递增版本合并报名状态，保留帖子点赞、收藏、返回缓存。断网不虚增人数，丢失响应可安全重试。
- 禁言/锁帖停止新报名和重开，但保留退出与结束招募；公开招募中的双方屏蔽释放相关名额，恢复屏蔽不恢复报名；匿名招募与公开屏蔽隔离，避免通过报名结果关联身份，隐藏匿名讨论仅释放本人名额；账号注销清理相关报名。

## 协议与迁移

schema 8，`buddiesEnabled` 能力开关；新增 `hyt_buddies`、`hyt_buddy_members`、`hyt_buddy_json`，保留原帖子、评论与旧通知。新接口 `buddies.join` / `buddies.close` / `buddies.members`；`posts.list` 新增 `joined` 范围，新增 `buddy` 通知类别。数据库表与辅助函数拒绝直接客户端访问。旧服务隐藏新入口，已有帖子仍可阅读。

私有服务升级通过独立、一次性激活分支执行，沿用邀请码；联调完成清理临时账号、帖子、报名、通知和媒体。未执行前不计为已上线。
