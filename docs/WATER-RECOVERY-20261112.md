# 接水恢复候选修复 · 2026-11-12

基于 main 780bbc85c0b70e8d9273129eca666d7141e21e42（1.2.1 /145）。仅测试；不合并、不发布、不改版本或更新配置。

## 证据

用户截图显示旧热水记录处于 WATER_WAIT，阻挡另一个出水口。上次 PR #50 只处理空会话、明确空闲或替换订单；持续不完整/旧响应无法核对，旧记录仍全局占用。这是可复现的状态机缺口，但截图不能证明实际响应内容或机身已停水。未收集/提交真实账号响应。

## 修改

保留严格设备核对；用户先尝试核对失败后，另行二次明确确认「亲眼确认机身已停水，仅移出本机记录」。新状态 archived_unverified 不等于远端结束/已付款，不发送网络命令、停止、结算或退款，也不伪造 deviceEnded、endedAt 或 billConfirmed。

待核实记录保留在原加密账号存储，下一笔启动后仍可查看订单；同账号重连保留，退出/换账号遵循既有隔离。达到100条时拒绝新增而非静默删除。历史费用仍需最近消费或官方端核对，本次不自动结算历史订单。

下一笔仍需重新核对报价并明确确认；新设备忙或非空缺字段状态禁止启动。空会话沿用既有无会话规则。移出记录不会自动启动。更新延迟判断认识新的本地归档状态。

参考公开 JUWPHub edf81286f26673968d4a804b6fd6bf6fc13f35ef 对本地会话与远端费用的区分，未照搬固定超时自动清除机制。

## 验证边界

441项前端测试、TypeScript和Vite构建通过。新增 Kotlin 用例检查明确确认、归档/查询/结束零命令、无捏造结束/付款、忙或不完整设备不解锁。本地没有 Android SDK，Gradle下载网络不可达，原生结果需另记 CI；未真机验证。

仍需问题手机验收：确认机身停止后先严格核对，再明确本地归档；重开及下一单后旧订单仍可查看；忙设备不启动，其他空闲设备重新确认；真实扣费对照官方账单；换号及重连不串记录。此候选不代表该设备问题已彻底修复。
