# PR #1 审查与修复记录

## 结论

可作为“学校授权教务连接的基础框架”合入，不能称为“已支持邯郸学院账号登录或自动同步”。默认注册表为空，界面明确提示未接入，不请求学校账号、密码或 Cookie。

审查基线：PR head `45db78f2049a0800ccb4ea125c6e49d4b4a3d459`，main `b413f3ac83ac6f1b0b97420d8a4837bf186181f8`。昨天的未推送本地检查点在环境维护中被清理；本次从原仓库重建修复并重新运行检查，没有把旧测试结果冒充为本次验证。

## 合并前修复

1. **退出后的异步回写**：原控制器在获取数据期间断开连接后，迟到的响应仍可能重新填充快照。增加操作代次，取消/断开后旧授权与旧请求结果失效；获取数据后再次检查会话状态。
2. **清理依赖连接页面**：原连接页面销毁后，过期/刷新失败可能没有通知主页面，留下旧授权视图。增加 App 生命周期订阅，失效后切回原本本机数据，同时清除已选课程和重叠课程列表。
3. **撤销失败残留**：原 disconnect 在远端撤销成功之后才清数据。现在先清本机记录，再尝试远端撤销；失败时明确区分“本机已清除”与“学校授权未确认撤销”，不显示假成功。
4. **错误信息泄露**：不再直接把连接器异常字符串显示给用户，避免异常 URL、token、Cookie 等被意外带到界面。
5. **数据边界**：拒绝空白/重复课程编号、空白课名、空教学周、超过当前学期的教学周、溢出日期及非法分数；颜色限制到现有颜色池。作息数据仅在独立验证并去除未知字段后接受。
6. **并发刷新与只读边界**：前台与连接页同时刷新时复用一次请求，重复导航不创建独立会话。授权课程只读，不误用本机课程编辑/删除；用户明确选择授权视图，本机管理不会覆盖或混入授权记录。
7. **v0.3.1 集成**：保留新版节次网格、全屏编辑、独立作息、payload v2 迁移、文件导入和全部本地课表功能。学校未提供作息时显示示例节次说明，课程仍按实际时间定位；成绩学期选项来自数据，避免硬编码演示学期。
