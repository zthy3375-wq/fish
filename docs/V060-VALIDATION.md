# v0.6.0 空闲教室测试说明

基于main `6a8014b`，分支feature/free-classrooms-v060；不合并main、不部署网站。沿用Android官方WebView认证、CookieManager和原生加密会话；独立只读教室连接器，不读取或改写个人课程来计算占用。

入口：教务→教学管理→空闲教室；课表页“查空闲教室”。不增加底部Tab。首次进入加载学校筛选项，选日期/节次后查询。日期、周次、星期互相对应，使用学校校历并由学校日期接口再次校验；校区、楼号、作息从学校加载。

列表按教学楼分组，显示学校返回的场地名称/类型/容量及本次查询保证的空闲节次；不凭未查询的其他节次夸大连续可用时间。展开教室从学校独立读取全天占用，并显示连续空闲段。体育场所等保留学校原类型，空闲不等于允许进入自习。

仅使用5分钟进程内短缓存，按学期/日期/校区/楼号/节次完整区分。筛选变化立即作废旧结果；错误后上次同条件记录明确标记“当前未知”；缓存过期不能冒充现状。主动登录和退出学校账号清除教室缓存，并阻止旧请求回填。

## 检查与真机范围

- Web测试、类型检查与生产构建：见本PR Quality作业。
- 编译进APK的教室适配器测试覆盖实际字段、位掩码、分页、零结果、异常/部分响应、日期错配、会话过期、稀疏占用、缺失映射、隐私字段过滤。
- 客户端测试覆盖相同条件请求合并、缓存隔离、失败保护、账号代际清理、错误查询响应拒绝。
- 浏览器回归使用合成原生响应，覆盖旧课表/成绩路径和360/390/430宽度的教室查询、全天未知状态、失败缓存提示与筛选失效。不是学校账号验收。
- Android原生debug/release单元测试和APK构建：见本PR Android作业。
- 学校页面与接口已真实核验，具体证据见 [研究记录](research/HANDAN-CLASSROOMS.md)。新APK中的WebView完整链路仍为“待真机验证”。

## 最小真机操作

安装测试APK后，使用已有学校连接进入教务→空闲教室；选择今天、教学楼和起止节次，点查询，展开一个教室检查全天安排。没有学校连接时只在官方页面完成一次登录。

本环境先前的临时SDK和测试签名文件已被工作区维护清理，本次由CI重新编译APK。CI debug签名可能与先前本地包不同。如覆盖安装提示签名冲突，先保留原应用和个人课表备份，不直接卸载；本次额外构建 `org.handancampus.app.classrooms` 并行测试包，名称“邯郸校园·教室测试”，可与旧应用共存，不修改旧应用及其数据。并行包需要在自己的官方WebView内首次登录一次，不能跨应用读取旧包的Cookie。普通包仍复用原包内的学校会话。
