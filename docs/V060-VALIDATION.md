# v0.6.0 空闲教室测试说明

基于main `6a8014b`，分支feature/free-classrooms-v060；不合并main、不部署网站。沿用Android官方WebView认证、CookieManager和原生加密会话；独立只读教室连接器，不读取或改写个人课程来计算占用。

入口：教务→教学管理→空闲教室；课表页“查空闲教室”。不增加底部Tab。首次进入加载学校筛选项，选日期/节次后查询。日期、周次、星期互相对应，使用学校校历并由学校日期接口再次校验；校区、楼号、作息从学校加载。

列表按教学楼分组，显示学校返回的场地名称/类型/容量及本次查询保证的空闲节次；不凭未查询的其他节次夸大连续可用时间。展开教室从学校独立读取全天占用，并显示连续空闲段。体育场所等保留学校原类型，空闲不等于允许进入自习。

仅使用5分钟进程内短缓存，按学期/日期/校区/楼号/节次完整区分。筛选变化立即作废旧结果；错误后上次同条件记录明确标记“当前未知”；缓存过期不能冒充现状。主动登录和退出学校账号清除教室缓存，并阻止旧请求回填。

## 最小真机操作

安装测试APK后，使用已有学校连接进入教务→空闲教室；选择今天、教学楼和起止节次，点查询，展开一个教室检查全天安排。没有学校连接时只在官方页面完成一次登录。

本环境先前的临时SDK和测试签名文件已被工作区维护清理，本次由CI重新编译APK。CI debug签名可能与先前本地包不同。如覆盖安装提示签名冲突，先保留原应用和个人课表备份，不直接卸载；本次额外构建 `org.handancampus.app.classrooms.fix1` 并行测试包，修复版名称“邯郸校园·教室修复”，可与旧应用共存，不修改旧应用及其数据。并行包需要在自己的官方WebView内首次登录一次，不能跨应用读取旧包的Cookie。普通包仍复用原包内的学校会话。

## v0.6.0.1 真机反馈修复

用户反馈：Android加载筛选项显示SCHEMA，且入口难找。已读取学校公共jquery.extends.contact-min.js，确认其覆盖Array.prototype.filter/some的回调参数为(index,value)，every直接返回true。原适配器按标准ES数组回调处理选项，导致有效选项被过滤为空。

先注入等价学校数组行为复现：原代码3个操作全部失败；修复采用显式循环校验，不修改学校全局对象。新增回归覆盖选项、分页查询、全天占用和无效节次拒绝。

入口改为首页顶部独立卡片、教务页第一项；移除原教学管理列表里的重复入口，保留课表快捷访问。不增加底部Tab。Android修复版versionCode61，versionName0.6.0.1-test。临时CI签名不能恢复旧测试包的私钥，因此提供独立fix1测试包，与旧应用并存，保留原数据；正式固定签名仍需后续配置。
